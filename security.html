도입 문의

Security.

폐쇄망 설치, 권한 통제, 감사 로그는 기본값입니다.

Toaster는 고객 환경 안에 설치됩니다. 데이터가 밖으로 나가는 범위를 먼저 정하고, 그 위에서 모델과 에이전트를 만듭니다.

01 · Security

설계 단계부터
넣어 둔 네 가지.

학습·검색 보강에 쓰는 로그는 비식별 처리 후에만 쌓습니다. 감사 로그는 따로 보관하며, 보관 기간과 환류 승인 절차는 고객의 보안 정책에 맞춰 설정합니다. 개별 규정 준수 여부는 고객 환경에서 함께 확인합니다.

  • 01

    프라이빗 배포

    온프레미스·폐쇄망(망분리 포함) 환경에 설치합니다. 학습과 서빙, 평가까지 외부 API 없이도 고객 GPU에서 처리할 수 있으며, 외부 모델 API를 쓸지는 고객이 정합니다.

  • 02

    권한 선검증

    조직도·권한 시스템을 연동해 권한을 가장 먼저 확인합니다. 연동하면 열람 권한이 없는 자료는 검색 대상에서 빠집니다.

  • 03

    입력 보안 체크

    개인정보 포함, 프롬프트 인젝션, 금지 주제, 업무 범위 이탈 여부를 먼저 판단하고, 위반 유형별로 정해 둔 응답으로 대체합니다.

  • 04

    배포 전 보안 점검

    인젝션·탈옥·시스템 프롬프트 유출을 측정합니다. 치명적인 공격이 한 건이라도 통하면 그 버전은 배포하지 않습니다.

02 · Before you start

도입 전에
함께 확인합니다.

설치 환경과 운영 조건을 먼저 맞춰 두면 PoC가 늦어지지 않습니다.

  • 데이터와 모델 연결

    쓸 수 있는 자료와 접근 권한, 사내 모델 API 또는 외부 모델 API의 사용 범위를 확인합니다. 외부 API를 쓰는 경우 밖으로 나가는 데이터의 범위도 함께 정합니다.

  • 학습과 추론 자원

    웹 애플리케이션과 모델 실행 자원을 나눠 설계합니다. 필요한 GPU와 메모리는 모델 크기, 학습 방식, 동시 작업 수에 따라 정합니다.

  • 설치 환경과 폐쇄망

    온프레미스와 폐쇄망에 설치합니다. 폐쇄망에서는 모델 파일, 실행 이미지, 패키지 반입과 업데이트 절차를 미리 준비합니다.

  • 운영과 접근 정책

    사용자 역할, 데이터 보관, 백업과 복구 범위를 정합니다. SSO, 고가용성, 조직별 격리 같은 요구사항은 별도 설계 범위로 확인합니다.

03 · Integration

기존 업무 시스템과의
연결까지 봅니다.

문서 기반 지식 검색, 데이터베이스 질의, API를 쓰는 업무 자동화처럼 지금의 환경에 맞는 적용 방향을 함께 정합니다.

학습·평가 제품의 도입 범위, 업무 시스템 연동 범위, 운영 모델 서빙 범위는 목적에 따라 나눠 설계합니다.

기존 SI 파트너가 있다면 그 파트너가 Toaster 위에서 구축합니다. 벤더를 바꾸지 않아도 됩니다.
